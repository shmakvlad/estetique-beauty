# Выкладка на hoster.by

Сайт — обычные файлы плюс один PHP-обработчик для заявок.
Собирается на вашем компьютере, на хостинг уезжает готовый результат.

Настройка делается один раз. Дальше всё обновление — одна команда:

```
npm run deploy
```

---

## Шаг 1. Поставить lftp

```
brew install lftp
```

Одна минута. Нужен, чтобы заливать по FTP только изменившиеся файлы,
а не всю папку каждый раз.

---

## Шаг 2. Файл .deploy.env

Создайте в корне проекта файл `.deploy.env`:

```sh
DEPLOY_METHOD=lftp
DEPLOY_HOST=vh171.hoster.by
DEPLOY_PATH=/www/torapava.by
```

Он в `.gitignore`, в репозиторий не попадёт. **Пароля здесь нет.**

---

## Шаг 3. Логин и пароль FTP

В вашей домашней папке, вне проекта — файл `~/.netrc`:

```
machine vh171.hoster.by
  login ВАШ_FTP_ЛОГИН
  password ВАШ_FTP_ПАРОЛЬ
```

Закрыть от посторонних, иначе lftp его проигнорирует:

```
chmod 600 ~/.netrc
```

FTP-пользователя можно создать в панели: раздел **FTP-пользователи**.

---

## Шаг 4. Токен бота на сервере

Через **Менеджер файлов** в панели создайте папку `api` внутри
`/www/torapava.by`, а в ней файл `config.php`:

```php
<?php
return [
    'token' => 'токен бота от BotFather',
    'chat'  => '-5497218409',
];
```

`chat` — id группы, куда приходят заявки. Минус в начале — часть значения.

Три вещи про этот файл:

- в репозитории его нет и не будет — токен не должен попадать в git;
- выгрузка его не затирает, он внесён в исключения в `tools/deploy.sh`;
- рядом автоматически ложится `.htaccess`, закрывающий его от скачивания.

Токен в `notify.php` не вписывайте: этот файл перезаписывается при каждой
выгрузке.

---

## Шаг 5. Первая выгрузка

Сначала вхолостую — покажет, что собирается сделать, ничего не трогая:

```
npm run deploy -- --dry-run
```

Если в списке файлы сайта и путь верный — заливаем:

```
npm run deploy
```

Первый раз уедет около 6 МБ, дальше только изменения — пара секунд.

> Если lftp ругается, что каталога нет, попробуйте `DEPLOY_PATH=/`.
> FTP-пользователь может попадать сразу внутрь папки сайта.

---

## Шаг 6. Проверка

1. Открыть https://torapava.by
2. Зайти на любую процедуру — адреса вида `/uslugi/chistka/` должны
   открываться, а не показывать список файлов
3. **Отправить тестовую заявку** и дождаться сообщения в Telegram

Третий пункт главный: остальное видно глазами, а заявки ломаются молча.

---

## Если заявки не приходят

Причина будет в **Журналах сайтов** в панели.

| В логе | Что делать |
| --- | --- |
| `не найдены токен бота и id чата` | Файл из шага 4 не создан или лежит не там |
| `Telegram ответил 401` | Токен неверный — взять актуальный у BotFather |
| `Telegram ответил 400` | Неверный `chat`. У группы значение с минусом |
| `не удалось связаться с Telegram` | Хостинг не выпускает наружу. Написать в поддержку: нужен доступ к `api.telegram.org` |
| Ошибка 500, в логе пусто | Старый PHP. В панели переключить сайт на 7.4 или новее |

Проверить обработчик можно и без сайта:

```
curl -i -X POST https://torapava.by/api/notify.php -d "telefon=+375291234567&imya=Проверка"
```

Ответ `{"ok":true}` — сообщение ушло в Telegram.

## Что потом

Пока новый адрес не проверен, Netlify не трогайте — пусть работает
запасным. Убедитесь, что сайт отвечает и заявки доходят, и тогда проект
на Netlify можно удалить. Репозиторий на GitHub остаётся в любом случае:
это история правок и резервная копия текстов.

Осталось заполнить:

- **УНП** в подвале — сейчас заглушка, `data/site.json` → `brand.legal`
- **Яндекс.Метрика** — номер счётчика в `seo.metrikaId`
- **условия акции** на День Рождения — сколько дней действует скидка

---

## Про токен

Токен бота был прислан в переписку, а она хранится на диске. Вы решили
оставить его как есть — это ваше решение, просто имейте в виду: если
понадобится, заменить его можно в любой момент через **@BotFather** →
`/mybots` → **API Token** → **Revoke**, и вписать новый в файл из шага 4.
Правок в коде это не потребует.
